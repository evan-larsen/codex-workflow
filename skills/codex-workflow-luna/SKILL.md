# Codex Workflow Luna

Keep the main agent close to the user's direction and next small outcome. Use
one `luna_executor` (Luna High Fast) by default; it owns focused discovery,
implementation, local integration and proportionate verification. The main
agent handles user intent, scope decisions, authority and the final answer.
Known reversible micro edits may be handled directly when the exact seam is
understood and one coherent patch with a cheap check is sufficient.

Optionally use the shared read-only Luna High `investigator` for one material
blocking uncertainty outside the executor's discovery. Do not duplicate the
executor's investigation. There is no automatic auditor, tester or researcher
lane. Parallel workers require the user's explicit request and exclusive
ownership. Do not silently switch to Sol or broaden into an autonomous program
when scope grows: keep the user's current lane and make the scope decision
visible, with a recommendation when a different workflow would help.

## Coordination contract

Keep this explicit activation active through related follow-ups; end it when the
coherent outcome is complete. User and host instructions take precedence.
Use compact capsules with `fork_turns: "none"`: outcome, acceptance criteria,
exclusive mutable ownership, starting references, constraints, authority, and
proportionate verification. Do not override packaged role models or reasoning.
Workers own their local discovery; avoid duplicate evidence lanes. Preserve
unrelated work. No nested coordinator by default.

Reuse workers while ownership and the causal question remain useful. Send only
changed requirements and material evidence. Collect defects into one prioritized
repair packet, repair the in-scope set together, then recheck affected evidence.
Use event-driven waits within host limits; avoid status polling and routine
worker progress relays. Keep user updates required by the host.

The implementation owner verifies a stable change once. Trust clear passing
proof unless new edits or evidence invalidate it. Choose checks by changed risk:
critical state, security, migration, release or shared contracts merit regression
protection; low-risk edits often need only source and diff inspection. Read-only
discovery runs no tests or environment checks by default; use a targeted
observation only when source cannot distinguish a named uncertainty.

No automatic memory files, project documentation framework, closure agent,
Companion, or worker statistics. Update technical documentation only when the
requested change makes it inaccurate. Git, external and destructive mutations
retain the user's authorization boundaries. Report outcome, changed surfaces,
actual evidence, residual risk and any next action concisely.
